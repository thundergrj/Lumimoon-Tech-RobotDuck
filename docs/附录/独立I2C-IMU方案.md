# 独立 I²C IMU 方案

[返回首页](../../README.md)

本附录只供明确使用独立 LSM6DSV16X 模组与对应运行时的套件。当前默认 BOM 使用 ID 200 的 IMU to DXL，不照本页接线，也不要求主控 I²C 扫到总线板内部芯片。

## 1. 接线与系统必须一起核对

核对模组的输入额定电压、逻辑电平、SDA、SCL、GND 和地址选择脚。旧教程对应的模组使用 3.3 V，不能直接接 5 V。

用当前 ZERO 3W 引脚表和镜像 overlay 确认物理针脚。物理针脚、I²C 控制器编号和 Linux `/dev/i2c-N` 不是同一个概念，不能只看到“I²C”字样就选任意两针。

本项目旧实操记录曾使用 27/28 脚与 I²C4-M0，对应 `/dev/i2c-4`；其他连接或镜像不一定相同。Qwiic/HAT 上的独立 I²C 口也可能映射到另一条总线。

## 2. 先确认设备身份，再读物理量

在没有其他程序操作该总线时：

```bash
ls -l /dev/i2c-*
# 仅当实际配置确为 I²C4 时
sudo i2cdetect -y 4
```

LSM6DSV16X 地址通常由硬件选择为 0x6A 或 0x6B，实际以模组说明为准。读 `WHO_AM_I` 并与该芯片资料核对；地址有应答只说明线上有设备，不证明型号正确。

使用该芯片支持的驱动配置采样率和量程，先把加速度与角速度换算到明确物理单位。旧文中的寄存器脚本是特定模块的历史记录，不作为跨固件通用安装脚本。

## 3. 静止、六面与动态检查

静止时加速度模长接近 1 g，角速度接近静止偏置。再缓慢翻转各个面，确认三个轴分别能读到正负方向，静止稳定后其余分量与摆放一致。

手持运动时模长不要求始终等于 1 g；不能拿动态数据套静止判据。原始加速度与投影重力符号不同，应按运行时定义检查。

检查持续读数是否新鲜、是否偶发 NAK/超时。确认线路、上拉、地址、电平与供电，不把一次崩溃后的总线状态直接判为传感器损坏。

## 4. 接入 robotd 才算完成

独立脚本能读到数据之后，还要让配套 robotd 使用正确来源，确认它正在读取该模组，而不是仍等待 ID 200。脚本退出后交给主程序独占访问。

完成固定、方向采集与运行端验证，继续[第 06 章](../06-标定HOME位与IMU.md)。没有 IMU 适配能力的运行时，不通过更换网页选项来假装已经接入。

系统准备见[第 04 章](../04-烧录系统.md)，方向标定与持久保存见[第 06 章](../06-标定HOME位与IMU.md)。寄存器配置、总线号与地址以当前模组和系统版本为准。
