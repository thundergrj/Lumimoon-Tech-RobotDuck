# 摄像头扩展与网络恢复

[返回首页](../../README.md)

摄像头放在站立、坐下、行走与联网稳定验收之后。分开验收传感器采图、视频编码、WebRTC 和 Studio 播放，不一次性安装全部组件并开启自启动。

## 1. 安装与散热

完全断电后连接 IMX219 与匹配 FPC。金手指朝向取决于两端连接器触点，不能统一描述“朝上/朝下”。插到底、排线无歪斜、锁扣闭合，线材不挤在活动关节或散热器锐边。

镜头无遮挡，主控有足够散热空间。记录新增摄像头和支架的重量与位置，避免明显改变头部负载或重心。

## 2. 先保存基础状态

保存镜像、内核、摄像头 overlay、GStreamer 版本和原配置，确认 SSH、本机登录和 Studio 正常，机器人已卸力。只使用与当前 OS/驱动组合匹配的媒体软件包，不复制另一个系统版本的库来覆盖系统目录。

如已有 mediad，先停止，避免两套程序抢相机；首次验证期间不启用自启动。

## 3. 第一步：传感器识别和独立采图

在配套系统上查看：

```bash
sudo dmesg | grep -Ei 'imx219|rkisp|csi'
v4l2-ctl --list-devices
media-ctl -p
```

工具未安装时使用该镜像提供的安装方式，不先升级全系统。确认哪个节点是真正图像输出，不能把 `/dev/videoN` 全当摄像头。

确认 capture 节点空闲、当前驱动支持相应模式后，可使用以下**低分辨率示例**做短时采图；实际节点、格式与尺寸以设备支持为准：

```bash
gst-launch-1.0 -e v4l2src device=/dev/video0 num-buffers=30 \
  ! video/x-raw,format=NV12,width=640,height=480 \
  ! videoconvert ! jpegenc \
  ! multifilesink max-files=1 location=/tmp/microduck-camera-%02d.jpg
```

打开实际生成的图片，确认不是测试图或旧文件。此步骤通过只证明该捕获路径能产出图像，**不证明 Studio 视频已可用**。

## 4. 第二步：插件、硬件编码和配置路径

在媒体服务实际使用的环境中检查 `v4l2src`、`webrtcsink`、`webrtcbin`、`mpph264enc`、`h264parse` 和 RTP 相关组件。`gst-inspect-1.0` 能列出插件，还要实际验证编码与格式协商。

某些插件需要特定 GStreamer/GLib、MPP/RGA 用户库和内核，不能只因为“都是 aarch64”就认为能互换。硬件编码节点权限、格式/stride 转换、H.264 profile 和 WebRTC 协商都可能使服务监听但无画面。

用 `systemctl cat mediad.service` 确认配置与环境。媒体默认配置可能是 `/etc/robot/robotd.toml`，而 robotd 使用 `/etc/robot/feetech-ft5/robotd.toml`，两个路径不能混为同一份文件。

## 5. 第三步：手动启动，核对真实视频帧

仅在前两步和配套兼容性检查通过后手动启动服务。核对实际来源是 `camera`，不是 `test` 测试图案。

在 Studio 摄像头页验证：服务在线 → 信令与媒体连接成功 → 解码帧持续更新 → 实际移动场景能看到变化。默认 8443 是信令端口，浏览器还要建立媒体链路；只转发 SSH 的 8000 端口不自动带上视频。

页面“服务在线”通常来自只读 hello，仅代表服务回应，不证明传感器和出流正常。固定照片、配置 source=camera 和静态测试图都不算真实播放通过。

## 6. 负载、联网和自启动分开验收

先用配套系统支持的低负载参数，观察温度、是否降频、CPU/内存、控制节拍和 SSH。依次测试无观众、一个浏览器播放、停止播放、重新连接，再复查基础站立和行走。

最后才启用开机自启动，并在冷启动、重复连接和持续运行后复测。不要因一张采图成功就启用服务，也不随意用软件旋转或软件编码替代硬件路径后继续宣称负载相同。

## 7. 启用后异常的回退

若视频启动后出现 SSH、网页、系统响应异常，先停止新增服务，保留机器人参数与标定。在能操作的本机终端执行：

```bash
sudo systemctl disable --now --no-block mediad.service
systemctl is-enabled mediad.service
systemctl status mediad.service --no-pager
sudo journalctl -u mediad.service -b -n 150 --no-pager
sudo journalctl -k -b -n 150 --no-pager
```

“disabled”表示取消自启动，不等于停止已经完成；应同时确认进程状态。若进程阻塞、系统已无法交互，记录现象并使用本机恢复流程，不能声称远程回退已成功。

再检查 SSH 配置与服务：

```bash
sudo sshd -t
systemctl status ssh.service ssh.socket --no-pager
sudo journalctl -u ssh.service -b -n 100 --no-pager
```

配置正确后才重新启动 SSH。必要的正常重启应在卸力与日志保存后进行，重启后先验证基础联网，不立即恢复视频。

## 8. 本项目经验的验证边界

一次调试中 IMX219 已识别且能采到真实 JPEG，但原先缺少视频服务与 WebRTC 组件。后续媒体组件和服务启动后出现 SSH 异常，最终主控失联；当时远程停用与关机均未确认成功。

这说明必须把摄像头服务纳入回退排查，**尚不能据此确定过热、某个用户库或某个内核驱动就是根因**。该次媒体组合不作为客户已验证方案，也不写成默认安装步骤。
