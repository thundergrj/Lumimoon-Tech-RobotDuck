# 04-烧录系统

[返回首页](../README.md) · 上一章：[装配与接线](03-装配与接线.md) · 下一章：[配置 Microduck Studio](05-配置Microduck-Studio.md)

**目标：**完成系统烧录、配网与维护入口，确认重启后仍能连接。此阶段不发送站立和行走命令。

## 1. 选择镜像，先核对版本

### 本项目自制镜像下载

- **镜像文件：**`microduck-configured.img`
- **下载地址：**[百度网盘：microduck-configured.img](https://pan.baidu.com/s/1SpQd2iEvG76W8MknUfTxvg?pwd=4a32)
- **提取码：**`4a32`
- **来源：**本项目自行制作的系统镜像。

下载完成后，按下文校验文件并烧录。该文件为 `.img` 镜像，可在烧录工具中直接选择，无需按压缩包解压。镜像的制作日期、内置软件版本、登录说明及 SHA256 校验值待补充，不能仅凭文件名判断其具体配置或验收状态。

### 使用前核对

优先使用随货指定、已在同批硬件验收的完整镜像，包含匹配的 HD1910 `robotd`、Studio、小助手、模型和出厂标定模式。填写[版本记录](附录/装机与验收记录.md)，核对镜像文件名、发行版本、日期与 SHA256。

**原生 Radxa Debian 不等于 Microduck 运行镜像。** 单装网页界面也不会自动具备飞特控制、IMU 识别和模型运行能力。只有原生系统时，需先由发货方补齐匹配的运行时安装包，再进入第 05 章。

不要把 Debian 12 与 Debian 13 的 Python、GStreamer 插件或运行库混装，也不为“修兼容”直接替换全系统运行库。原系统上已有校准数据时，烧卡前先备份。

公开社区镜像也可作为来源参考：例如 [microduck-replica 镜像说明](https://github.com/fanhao375/microduck-replica/blob/master/software/image/README.md)等。

## 2. 校验下载文件

在下载镜像的**电脑**上计算 SHA256。以下命令对应上述自制镜像；使用其他文件时替换文件名。命令在镜像所在目录执行，也可以填写完整文件路径。

```powershell
# Windows
Get-FileHash .\microduck-configured.img -Algorithm SHA256
```

```bash
# macOS
shasum -a 256 microduck-configured.img
# Linux
sha256sum microduck-configured.img
```

将结果与制作方提供的同名文件 SHA256 逐字比较。当前教程尚未附上该镜像的校验值，可先记录下载文件的摘要；只有取得制作方的原始摘要并比对一致后，才能记录为“校验通过”。

压缩包和解压后的镜像是不同文件，其摘要也不同。若另行下载 `.img.xz` 等压缩包，不要拿压缩包的摘要核对 `.img`。

## 3. 烧录 microSD

1. 用 [balenaEtcher](https://etcher.balena.io/) 或发行方指定工具。
2. 选择下载完成的 `microduck-configured.img`。使用其他压缩镜像时，工具支持的压缩格式可直接选择；不支持时按发行说明解压为 `.img`。
3. 选择目标 microSD，仔细核对容量与设备，避免选中电脑硬盘或其他移动盘。
4. 执行写入并等待工具验证完成。
5. 安全弹出卡，瑞莎断电后插卡。

已有 eMMC 可能影响启动介质选择。启动后看不到刚烧的版本时，先核对实际从哪块盘启动，不反复覆盖卡。eMMC/Maskrom 过程按 [Radxa 安装文档](https://docs.radxa.com/en/zero/zero3/getting-started/install-os)和镜像适配说明进行，不对未知设备号执行 `dd`。

## 4. 首次启动与联网

初次配置可让瑞莎单独使用 5 V USB-C 1 供电，舵机电池断开。整机通过 HAT 供电时，按第 03 章使用单一路径，不临时并接第二路电源。

接屏幕键盘按随货账户登录。不同镜像账号、首次密码和 SSH 策略可能不同，本教程不提供跨镜像通用默认密码。

命令在**瑞莎终端**执行：

```bash
cat /etc/os-release
uname -m
hostname
ip -brief address
nmcli device status
```

如使用 NetworkManager，可交互式连接 Wi-Fi，避免把密码写进命令历史：

```bash
nmcli device wifi list
sudo nmcli --ask device wifi connect "你的WiFi名称"
hostname -I
```

完整配套镜像可能提供热点配网，按其发行说明连接。不能假设原生系统或单独安装的 Studio 自动有热点。

电脑与鸭子连接同一可互通的局域网。先记实际 IP，再在**电脑**连接；下列 `192.168.1.123` 只是示例，必须替换：

```bash
ssh radxa@192.168.1.123
```

不要默认仍是上一次 IP。可在路由器查看租约，条件允许时为主控保留 DHCP 地址；`.local` 解析取决于镜像和电脑环境。

## 5. 确认 SSH 可以恢复系统

若镜像出厂只允许密钥登录，先按配套说明在 Studio“更多”中登记自己的 `.pub` 公钥，或在本机终端配置授权。私钥不上传、不发给售后。

瑞莎本机可检查：

```bash
systemctl status ssh.service --no-pager
sudo sshd -t
```

确认配置无误且允许所需登录方式后，可启用服务：

```bash
sudo systemctl enable --now ssh.service
```

首次装机至少保留一种网络失效后的本机恢复方式。LED 常亮只能说明某些电路有供电，不能代替系统在线验收。

## 6. 核对串口与总线占用

配套镜像应已配置总线使用的 UART。先检查，不盲改其他串口：

```bash
ls -l /dev/ttyS2
systemctl cat robotd.service
systemctl is-active serial-getty@ttyS2.service
sudo fuser -v /dev/ttyS2
```

实际总线确为 ttyS2 时，关闭这个口上的登录终端：

```bash
sudo systemctl disable --now serial-getty@ttyS2.service
sudo systemctl mask serial-getty@ttyS2.service
```

ZERO 3W 的 UART2_M0 在引导阶段也可能是调试控制台，仅关闭 Linux getty 不等于释放 U-Boot。按[官方接口说明](https://docs.radxa.com/en/zero/zero3/hardware-design/hardware-interface)和当前镜像适配方案核对启动配置，不把其他镜像的 `/boot` 配置直接覆盖过来。

正常运动时总线由 robotd 占用；Studio 接管时由 Studio 独占。不要额外开扫描脚本“验证一下”。

## 7. 先保留最小功能，验证在线稳定

首次验收只需要主控网络、robotd、Studio 与必要的辅助程序。摄像头、语音等扩展先不启用。若系统已存在且启用了尚未验收的 mediad，可在确认全机卸力后暂停并取消其自启动：

```bash
sudo systemctl disable --now --no-block mediad.service
```

没有该单元时不需补装。桌面镜像若会自动休眠，先在桌面电源管理中关闭空闲睡眠；无人值守的机器人镜像可按维护要求屏蔽系统休眠目标，并记录此改动：

```bash
sudo systemctl mask sleep.target suspend.target hibernate.target hybrid-sleep.target
```

观察至少数分钟：SSH、Studio 持续可达，温度与负载无异常，空闲时不会失联。再正常关机、重新上电验证一次。不要把一次 ping 成功当作稳定性完成。

- [ ] 实际系统、启动介质、CPU 架构与配套说明一致。
- [ ] Wi-Fi、IP、SSH 登录方式明确，本机恢复入口可用。
- [ ] ttyS2 与 getty/引导控制台按本镜像核对完成。
- [ ] 未混装跨系统版本的视频组件，扩展服务未影响基础在线。
- [ ] 空闲和重启后的联网检查通过。
